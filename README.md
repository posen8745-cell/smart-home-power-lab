# 智慧家庭分區用電監測與過載警示

基隆私立二信高中・普通科數理班・張博程的自主學習作品。

## 我為什麼想做

家中一樓餐廳有氣炸燒烤爐、微波爐、電鍋、IH 飯鍋和飲水機。同時使用高功率電器時，20A 總開關曾跳脫，一樓整層就沒電。我因此想到：能不能先看出目前是哪條分路的負載太高，再提醒家人錯開使用？

我先做一個虛擬配電箱，讓人從「總開關 → 三條分路 → 各項電器」看用電變化，再比較沒有管理和啟用負載管理的差別。

**想法與功能需求由我提出，程式與介面由 AI 協助完成。我負責操作、觀察結果、提出問題，再請 AI 協助修正。** 目前不是全部由我獨立寫出的程式，我也還在學習計算、量測和控制的差別。

## 我的修改過程與學習紀錄

這個作品的起點是家中一樓餐廳的 20A 總開關曾跳脫，整層就沒電。我提出「負載偏高時先提醒」的構想，希望能看出哪些電器同時使用會讓負載升高。

討論過程中，我指出操作太難懂、氣炸燒烤爐才是主要高功率電器，以及介面沒有開始監控。我也要求保留原本的分區監測架構。AI 依照這些回饋修改程式與介面；我的主要參與是提出生活情境、功能需求、查看結果與回饋修改，還不是獨立完成全部程式。

| 我注意到的問題 | 修改後 |
|---|---|
| 示範主角與家中情境不夠貼近 | 以氣炸燒烤爐為主要高功率電器，保留餐廳五項電器 |
| 操作太多步，難以看出用途 | 保留三分路架構，集中三個比較情境，進階設定收起 |
| 缺少持續監控的流程 | 加入開始／停止、每秒讀值、狀態變化通知及監控 CSV |
| 想呈現手機收到預警的概念 | 加入頁面通知示意，明確區分真實遠端推播 |

### 五個情境的模擬檢查

2026/11/10，由 AI 協助執行目前程式的計算與通知判斷。以下是預設虛擬負載的結果，**非家中實測，也非我已獨立完成的實驗紀錄**。我自己的操作 CSV、截圖與解釋仍待補上。

| 情境 | 全箱要求 W | 全箱供電 W | 分路 A 供電 W | 通知判斷 |
|---|---:|---:|---:|---|
| 一般用電 | 507 | 507 | 0 | 首次正常，不發通知 |
| 開啟氣炸燒烤爐 | 2007 | 2007 | 1500 | 用電負載偏高，請留意 |
| 再加入微波爐 | 3107 | 507 | 0 | 分路 A 模擬跳脫 |
| 啟用負載管理情境 | 3107 | 2007 | 1500 | 負載管理已調整模擬供電 |
| 回到一般用電 | 507 | 507 | 0 | 負載已降低 |

五個情境的計算與通知判斷皆符合預期；同時檢查相同狀態不重複通知、重複按開始不建立多個計時器，以及停止後不再新增監控讀值。首頁「製作與檢查紀錄」可查看此表並下載 CSV。

比較時不能只看供電變少就當成節電：跳脫會讓電器無法完成工作；負載管理暫停微波爐，也不代表它已完成加熱。管理後全箱供電約 18.25A，仍達這個作品自訂的提醒門檻，不能宣稱已經安全。

### 整理後的反思與下一步

這次整理讓我注意到，要求功率和供電功率不能混在一起看；分路跳脫和總開關跳脫，也會影響不同範圍。我目前想練習用自己的話解釋為什麼出現通知，再用不同情境對照結果。

下一步先依上表自行操作，保存監控 CSV 和畫面，補上預期結果、實際觀察及不符合時的追查。若要接入家中量測，仍需要在老師或專業人員協助下確認迴路與資料來源；真實手機推播也要另外驗證。

## 最簡單的操作

1. 開啟頁面，按 **開始模擬監控**。上方會顯示「模擬監控中」，筆數與最近讀值時間每秒更新。
2. 往下找到電器開關，開啟 **氣炸燒烤爐**。在預設背景負載下，全箱供電為 2007W、約 18.25A；分路 A 為 1500W、約 13.64A。程式判斷達到本作品的 80% 提醒門檻，在「監測結果」內產生手機通知示意。
3. 關閉氣炸燒烤爐，負載降回 507W；下一筆讀值會產生「負載已降低」的通知。
4. 按 **停止監控**，筆數、最近監控時間與通知不再更新。畫面仍可以切換電器或預覽情境，但不再新增監控紀錄。

也可以在監控中切換三個比較情境：

| 按鈕 | 想觀察的事情 | 預設結果 |
|---|---|---|
| 1. 一般用電 | 先看總開關與三條分路 | 照明、風扇、電腦、除濕機，共 507W |
| 2. 高功率同時使用 | 加入氣炸燒烤爐與微波爐 | 分路 A 要求 2600W，超過 1650W 模擬上限，A 跳脫；B、C 繼續供應 507W |
| 3. 啟用負載管理 | 相同需求，讓程式依優先等級調整 | 暫停微波爐，A 供應氣炸燒烤爐 1500W；全箱供電 2007W |

情境切換會重設該情境的度數、跳脫狀態與原有實驗事件；**持續監控不會停止，每秒監控紀錄與通知會保留**，下一次檢查會判斷新情境。這三個按鈕也可在未開始監控時先預覽，此時不新增監控紀錄與手機通知示意。

比較時要分清楚：**要求功率**是想一起使用的功率；**供電功率**是經管理與模擬跳脫後剩下的功率。第二個情境供電較少，是因為 A 跳脫，不能把它當成比較節電。第三個情境也只是先暫停微波爐，並不代表已完成加熱。

## 持續監控與通知

「開始模擬監控」每秒讀取目前設定的虛構負載，重新計算分路與總開關狀態，記下一筆資料。不會隨機改動瓦數，也沒有連接家中感測器；電器開關或情境改變，才會讓負載變動。

第一次讀到偏高或跳脫，或者狀態後來改變，才會產生新通知；相同狀態不會每秒重複提醒。可展示負載偏高、分路跳脫、總開關跳脫、負載管理與恢復提示。若復歸後負載仍偏高，通知會說明仍需留意，不會宣稱已經安全。

手機通知區位於「監測結果」內，**只是這個頁面的通知預覽，沒有真的傳到另一支手機**。原本的 Wi-Fi 手機展示頁也不會同步這些通知。

上方的「下載監控紀錄」不必先播放或前進 15 分鐘，就能下載已取得的每秒讀值。內容包含時間、全箱與三分路的要求及供電功率、額定設定、跳脫與管理狀態，並標示「模擬資料／手機實際推播未實作」。本頁最多保留最近 600 筆讀值及 60 則通知，總檢查筆數則繼續累加。

停止後保留最近紀錄；再按開始時會立即檢查當下狀態，若負載仍偏高也會再次提醒。按「重設本次紀錄」會停止監控，清除監控與原有實驗紀錄，但保留當下電器設定。重新讀取 JSON 會停止監控並重載一般情境，已有的每秒紀錄保留。重新整理頁面會清除所有本次資料。

切到背景分頁時，監控和度數播放會停止；回來後要手動重新開始。這不是全天候背景監測服務，也不能預測真實跳電時間。

## 保留原本的作品內容，減少主畫面的設定

主畫面保留配電箱、三條分路、電器開關、負載警示與管理結果，並加入開始／停止監控、每秒讀值與手機通知示意。電器的瓦數及優先順序預設收起，勾選「顯示電器進階設定」才顯示。

自行試其他組合時，可切換電器開關。若分路已模擬跳脫，先關掉部分電器或啟用管理，再按「模擬復歸」。復歸只是網頁操作，不是真實電箱的操作教學。

以下功能放在可展開區塊，第一次展示不需要操作：

- JSON 情境與示範資料。
- 分路 A 額定電流與示範電價。
- 前進 15 分鐘、播放時間、度數累計。
- 24 小時功率曲線、事件紀錄、CSV、計算方式。

每秒監控不會自動推進用電量試算。延伸區的「前進 15 分鐘」才把當下供電維持 15 分鐘的用電量計入實驗紀錄；播放每 1 秒前進一次，最多 24 小時。這不是電器真的需要使用的時間，也沒有固定讓五項電器依序排隊。改設定只更新當下結果，不會回頭改寫先前的紀錄。

## 虛擬配電箱怎麼分

| 項目 | 本頁示範設定 | 用途 |
|---|---|---|
| 總開關 | 20A | 依家中描述呈現，實際配電形式仍未核對 |
| 分路 A | 110V、15A | 餐廳五項電器，先假設共用一條分路 |
| 分路 B | 110V、10A | LED 照明、風扇 |
| 分路 C | 110V、15A | 電腦、除濕機 |

分路不一定等於房間。同在餐廳，也不代表真的接在同一條分路；這些標籤是虛構的，沒有量測核對家中接線。不能把分路額定電流直接相加當成總開關可供電量。

| 餐廳電器 | 假設輸入功率 |
|---|---:|
| 氣炸燒烤爐 | 1500W |
| 微波爐 | 1100W |
| 電鍋 | 700W |
| IH 飯鍋 | 1200W |
| 飲水機（加熱階段） | 700W |

氣炸燒烤爐是本次比較的主要高功率電器。瓦數都是可修改的假設值，不是家中機型的實測規格；微波爐應看輸入功率，飲水機沒有模擬待機、保溫和間歇加熱。

## 程式做了什麼

本頁以 `I = P ÷ V` 估算電流，固定使用 110V、功率因數 1 的簡化模型。度數則以 `E = P × t ÷ 1000` 累加，P 是瓦、t 是小時。

超過分路額定的 80% 會顯示提醒；超過 100% 會模擬跳脫。這是作品自訂規則，沒有模擬真實斷路器的延時、啟動電流或保護協調，不能預測實際何時跳電。本模型先處理分路跳脫，再檢查仍供電的分路是否超過總開關上限，並不代表現場一定以這個順序跳脫。

啟用負載管理時，先依「可延後 → 一般」暫停模擬供電，保留「必要」；同級時先暫停瓦數較高者。若必要負載仍超限，也會模擬跳脫。負載減少後會重新計算供電，沒有判斷食物是否煮熟，也不會操作真實家電。

錯開使用主要降低同時用電的功率，不會自動減少完成相同工作所需的度數。示範電費是度數乘自訂單價，並非正式電價計費。

## JSON、手機頁與 Wi-Fi 原型

首頁會讀取同層的 `mock_panel.json`，參考原本三條分路的額定電流；電器清單、三個情境與 20A 總開關設定內建在本頁。沒有 JSON 或格式不支援時，會標明改用內建備援資料，不會假裝讀取成功。

本頁只支援這個三條 110V 分路的簡化示範，不宣稱支援任意真實電箱資料。若更改 JSON 的分路額定，結果可能和上表的預設比較不同。

原有 `monitor.html` 與 `gateway.py` 保留為另一個 Wi-Fi 手機原型：

1. 只看展示：開啟 `monitor.html`，看 JSON 虛構情境。
2. 要做區域網路測試：電腦保留原儲存庫檔案，執行 `python3 gateway.py`，手機與電腦連同一個可信任網路。
3. 在手機開啟終端機顯示的網址，依原型畫面輸入本次示範碼。

GitHub Pages 不會執行 Python。手機頁仍是原本的獨立情境，不會同步首頁的電器開關、20A 設定、管理與跳脫結果。Python 原型也未連接合格電表，不代表已取得家中真實用電資料；不要把區域網路原型開放到公開網路。

「負載偏高時先通知手機」已能在首頁預覽通知內容，但真正的遠端推播仍是後續方向。這版沒有實際遠端推播，也沒有全天候背景監測。
