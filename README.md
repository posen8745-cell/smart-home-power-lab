# 智慧家庭配電箱｜分路用電監測與過載警示模擬系統

**作者：基隆私立二信高中・普通科數理班・張博程**  
**作品性質：高中電機自主學習｜模擬配電箱 JSON 資料｜網頁控制與電力計算**  
**完成內容：虛構配電箱、三條模擬分路、電器負載控制、過載／負載管理、時序資料及 CSV 輸出**

> **重要安全與作品定位**：本系統並未連接家中電箱，也未安裝電流互感器（CT）、電表、感測器或實體斷路器。`mock_panel.json` 的所有資料均為虛構。網頁上的「跳脫」「復歸」「停電」只是 JavaScript 狀態，**不具有任何真實電氣保護或控制能力**；不能用來評估居家線路安全、選擇斷路器或進行配線。切勿自行拆開或改造市電配電箱。

## 一、作品介紹與自主學習動機

我在學習 Python 及製作互動網頁後，想挑戰更直接與電機工程相關的主題。家庭中的電器並不是各自獨立接到電力公司，而是經由配電箱的總開關和不同分路供電。當一條分路接上多個電器，就需要考慮該分路的功率、電流與保護設計。

因此，我把原本「六種家電的用電計算」進一步改成「**虛擬配電箱 → 三個分路 → 電器負載 → 網頁監測**」的模型，使用 `mock_panel.json` 表示配電箱和每個電器所屬的回路。希望了解總負載與分路負載的差異，並透過對照實驗練習控制邏輯，而不是只顯示一個全家的耗電總數。

這是**第一階段的純軟體自主學習**，沒有進行現場電氣量測或控制。虛構分路並非任何特定住宅的配線圖。

## 二、自主學習目標

1. 認識配電箱總開關與分路保護的基本概念。
2. 理解示範電壓（V）、電流（A）、功率（W）和累積電能（kWh）之間的關係。
3. 學會用 JSON 把配電箱、分路、電器與示範情境分開存放。
4. 對每條分路分別計算用電需求，模擬「一條分路超限，但其他分路仍供電」。
5. 設計規則式負載管理、模擬跳脫、手動復歸與事件紀錄。
6. 產生每 15 分鐘一筆的虛構數據，繪圖並匯出 CSV 比較實驗結果。
7. 分辨「模擬電流」「實際量測」以及「正式保護設備」的不同。

## 四、JSON 資料規格

網頁使用 `fetch('./mock_panel.json')` 從同一層載入 JSON。重要欄位如下：

| 欄位 | 意義 |
| --- | --- |
| `source` | 固定 `SIMULATED_DATA_ONLY`，明確標示虛構資料 |
| `panel.id` | 虛構電箱識別碼 `DB-DEMO-001` |
| `panel.voltageV` | 假設固定電壓，預設 `110` |
| `panel.powerFactorAssumed` | 教學簡化假設為 `1` |
| `panel.mainBreaker.ratingA` | 虛構總開關額定電流，預設 `30` A |
| `panel.branches[].id` | 分路代號 `A`、`B`、`C` |
| `panel.branches[].ratingA` | 該分路示範上限（A），預設 `15 / 10 / 15` |
| `devices[].branchId` | 每個電器屬於哪一條分路 |
| `devices[].watts` | 電器假設功率（W），可在網頁中修改 |
| `devices[].priority` | `1` 必要、`2` 一般、`3` 可延後 |
| `scenarios[]` | JSON 預設情境、啟動電器及是否啟用管理 |
| `sampleReadings[]` | 供教學閱讀的虛構快照，非感測器讀值 |

JSON 資料範例（完整內容請看 `mock_panel.json`）：

```json
{
  "source": "SIMULATED_DATA_ONLY",
  "panel": {
    "voltageV": 110,
    "mainBreaker": {"id": "MAIN", "ratingA": 30},
    "branches": [
      {"id": "A", "name": "高功率家電", "ratingA": 15},
      {"id": "B", "name": "照明與風扇", "ratingA": 10},
      {"id": "C", "name": "資訊與除濕", "ratingA": 15}
    ]
  }
}
```

上例僅節錄 `panel` 主要欄位；網站使用的是包含 `schemaVersion`、`devices`、`scenarios` 等完整欄位的 JSON 文件。

**資料備援：** GitHub Pages 若無法取得 `mock_panel.json`，畫面會顯示「使用內建虛構資料」及錯誤狀態，仍可操作備援模擬。**要證明真正完成 JSON 載入，應確認網頁狀態顯示「已讀取 mock_panel.json」。** 直接雙擊 HTML 可能因瀏覽器的本機檔案安全限制，使用內建示範資料；建議以 GitHub Pages 或本機 HTTP 伺服器操作。

## 六、電學與保護概念（簡化模型）

程式將各電器功率加總，依假設電壓與 PF＝1 估算：

```text
P_分路 = 該分路中目前要求供電的電器 W 數總和
I_分路 ≈ P_分路 / 110 V
P_上限 = 110 V × 示範額定電流 A
E_kWh = Σ(每個 15 分鐘步進的實際模擬供電 W × 0.25 h / 1000)
```

例如分路 A：

- 模擬電鍋 700 W＋吹風機 1200 W，要求功率 1900 W。
- 假設額定上限：110 V × 15 A＝1650 W。
- 要求電流：約 17.27 A，超過假設上限。
- 不管理時，網頁立即設定**分路 A 模擬跳脫**；其他未超限分路仍可能繼續供電。
- 啟用智慧管理時，先暫停可延後的 1200 W 吹風機，分路 A 剩下 700 W，約 6.36 A。
- 若模擬供電 700 W 維持 15 分鐘，增加電能 `700 × 0.25 / 1000 = 0.175 kWh`。

**這是教學狀態機，不是真正的保護裝置特性。** 真實斷路器不會僅依「超過額定值」就瞬時跳脫，還需考慮時間電流特性、配線及保護協調。真實交流設備的實際電流也可能受功率因數、起動電流及波形影響。

80% 提醒只是本頁的**自訂教學閾值**，不代表建議家庭以此數字決定安全負載。總開關和分路的額定數值也只是模擬參數。

## 七、操作方法與對照實驗

1. 將 `index.html`、`mock_panel.json`、`README.md` 放在同一層，開啟 GitHub Pages 網站。
2. 查看「已讀取 mock_panel.json｜虛構資料」提示；若是備援，先檢查檔名與路徑。
3. 在「虛擬配電箱與分路連結」觀察總開關，以及 A、B、C 分路的電流與狀態。
4. 使用 JSON 情境選單或按下「實驗 A：不管理負載」：檢查分路 A 過載跳脫。
5. 按「實驗 B：智慧管理負載」：同樣的 1900W 需求，分路 A 改為保留 700W。
6. 點「前進 15 分鐘」，確認累積電量增加約 0.175 度。
7. 載入「跨分路同時用電」，觀察不同分路的負載與全箱功率。
8. 可以自行調整家電 W 數、開關、管理優先等級及分路 A 模擬額定電流。
9. 查看圖表和事件；按「下載 CSV 實驗紀錄」保存虛構時間序列。

**備註：** 網頁更改的參數不會自動寫回 JSON；需要長期修改預設內容時，請編輯 `mock_panel.json` 並重新部署。每個 15 分鐘步進是虛擬時間，不是實際監控時間。

## 九、GitHub Pages 部署與測試

GitHub Pages 可發布純 HTML、CSS、JavaScript 與 JSON 靜態檔案，沒有後端也能載入示範設定。

1. 建立儲存庫 `smart-home-power-lab`（Public）。
2. 把 `index.html`、`mock_panel.json`、`README.md` 放在 `main` 根目錄。**不要只上傳 ZIP，也不要把 HTML 改名成 `index-xx.html` 當作唯一首頁。**
3. 到 **Settings → Pages → Deploy from a branch → main → /(root)**，按 Save。
4. 部署成功後以 GitHub 顯示的網站網址為準；通常為 `https://posen8745-cell.github.io/smart-home-power-lab/`。
5. 網頁狀態應顯示「已讀取 mock_panel.json」。如出現內建備援，檢查 GitHub 是否缺少 JSON 或路徑不一致。
6. 若 GitHub Pages 出現 404／獨角獸錯誤，先看 **Actions → pages build and deployment** 與官方服務狀態，勿直接判斷是 HTML 程式錯誤。

## 十、現階段限制與未來研究

- 所有電流都是功率換算值，**不是電流感測器資料**。
- 110V 全箱、三分路、主開關 30A 是虛構的單電壓等效模型，不能當作實際住宅配電設計。
- 網頁的負載管理只改變模擬數值，不能遠端關閉家電或實體斷路器。
- 未模擬短路、漏電、溫升、三相或分相、線路阻抗、瞬間起動電流等真實現象。
- CSV 是瀏覽器中產生的示範紀錄；沒有即時資料串流、雲端背景監測及跨裝置保存。
- 費用是自訂 kWh 單價試算，與台電正式帳單不同。

**下一階段若要加入實測資料：** 可先在學校老師指導下，使用**隔離的低電壓直流教學電路**與安全的量測模組，驗證電流、電壓及負載功率是否與計算相符。若未來真的要量測家庭配電箱，所需的電流感測設備、隔離、通訊、校正及安裝方式必須由專業人員規劃；**不可自己打開配電箱、碰觸或夾設市電導線**。本版僅展示未來資料可能流入網站的概念，不提供配線教學。

### 學習歷程摘要

> 這次自主學習想把原本的家電用電計算，改成較接近電機工程的「虛擬配電箱」模型。我先用 JSON 建立總開關、三條分路與六種家電的資料關係，再讓 JavaScript 計算各分路的功率和電流，顯示模擬跳脫、智慧負載管理與用電曲線。透過電鍋加吹風機的對照實驗，我理解分路負載與整體總負載不同，也練習把控制規則寫成程式。這個作品還沒有連接真實電箱或量測設備，因此我將所有數值清楚標示為模擬資料。未來希望先從安全的低電壓教學電路學習實際量測，進一步比較公式與感測器讀值的差異。
