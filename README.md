# 智慧家庭分區用電監測與錯峰建議｜Wi‑Fi 手機展示原型 v3

**作者：基隆私立二信高中・普通科數理班・張博程**  
**定位：高中電機自主學習原型／商品化構想，非上市商品**

> ⚠️ **重要安全說明**：現階段只有虛構分路、JSON 示範資料、Wi‑Fi 區域網路網頁與負載建議。**未接家中配電箱、沒有任何真實電表或感測器連線，沒有接線與遙控斷電功能。** 配電箱施工、專業電力量測儀器選型與安裝必須交給合法合格的專業人員。網頁的過載提示不是電氣保護裝置，也不能據以調整家中斷路器或配線。

## 一、作品動機與未來產品願景

我想讓家人不只看見台電帳單的總用電量，而是能**從手機看出家裡哪些區域同時用電較多**，在使用電鍋、除濕機或其他高功率設備時，知道是否適合錯開使用時段。我因此將原有的家電功率模擬擴充成「分路監測 → Wi‑Fi 本機資料 → 手機查看 → 使用時段建議」原型。

我的長期目標是研究能否開發方便家庭安裝、清楚說明用電來源、重視安全與隱私的商品。但**現在沒有做出可以上市的硬體**，也未證明節電率或電氣保護效能。

## 三、系統架構

```text
【目前可操作原型】
 mock_panel.json（完全虛構）
             │
             ▼
 電腦 gateway.py（Python 3 內建 HTTP 伺服器）
   ├─ 模擬各分路用電與錯峰建議
   ├─ /api/status & /api/history（每 5 秒更新）
   └─ /monitor.html（手機版）
             │ 同一台可信任 Wi‑Fi 路由器
             ▼
        手機 Safari / Chrome

【未來的實測架構，尚未實作】
 合格分路電力量測器（專業安裝）
             │ 合法且隔離的數位資料介面
             ▼
  家庭閘道器／資料擷取器
             │ Wi‑Fi / 安全連線
             ▼
     手機儀表板／提醒
```

**與 GitHub Pages 的差別：** GitHub Pages 是 HTTPS 靜態網站，不能假設它能直接讀取家庭內 HTTP 裝置。瀏覽器可能對跨來源的本機網路請求施加限制。本版讓手機直接打開同一區域網電腦的 `monitor.html`，前端和資料 API 由**相同的閘道器位址**提供，避免這個問題。此方法只適合可信任局域網示範，不是正式產品的安全連線方案。

## 五、使用方式（先只測試虛構資料）

1. 解壓縮全部檔案到同一資料夾；電腦和手機使用**相同可信任的 Wi‑Fi**。
2. 電腦有 Python 3 即可，不需要安裝額外的 Python 套件。
3. 開啟終端機，在該資料夾執行：

   ```sh
   python3 gateway.py
   ```

   Windows 的 Python 命令若是 `py`，可改用 `py gateway.py`。
4. 電腦終端機會顯示手機連線用的區域網網址，例如 `http://192.168.1.5:8765/monitor.html`，以及**每次啟動才生成的 6 位示範碼**。範例 IP 只是示意，應以終端機實際顯示為準。
5. 手機連到同一個 Wi‑Fi，使用瀏覽器輸入終端機顯示的網址，再輸入示範碼。
6. 在手機切換「一般用電 / 高功率同時使用 / 錯峰後 / 跨區用電」，查看哪一分路用電最高、是否達自訂示範門檻以及建議事項。
7. 選擇「匯出畫面資料 CSV」可保存當前各區展示值。也可從 `index.html` 開啟原有互動模擬器。
8. 結束後回電腦終端機按 `Ctrl+C` 關閉網關。

**常見問題：** 手機連不上時，先確認電腦與手機在同一網段、電腦防火牆允許此埠、Wi‑Fi 沒有開啟裝置隔離（Client Isolation）。不要用路由器的 Port Forwarding 將本示範服務公開到網際網路。

**直接部署 GitHub Pages 也可以：** 上傳 `monitor.html`、`index.html` 和 `mock_panel.json` 後，`monitor.html` 自動讀取靜態 JSON 進行**離線展示**；這種方式不能取得本機網關或真實電箱的即時資料。

## 六、演示情境與數值

模型設定：固定 110V、PF=1、A 15A、B 10A、C 15A、總開關 30A。純教學示意，**不是住宅配線規範或安全額定建議**。

| 情境 | A 區 | B 區 | C 區 | 全部需求 / 模擬當前用電 |
|---|---:|---:|---:|---|
| 一般用電 | 0W | 67W | 440W | 507W |
| 高功率同時使用 | 1,900W | 0W | 0W | 1,900W，A 區超過示範 1,650W 門檻 |
| 錯峰後（假設稍後再用吹風機） | 700W | 0W | 0W | 700W，原需求 1,900W |
| 跨區用電＋錯峰示範 | 700W | 67W | 440W | 1,207W，原需求 2,407W |

在錯峰情境裡，1,200W 吹風機**只是從虛構同時使用清單移出**，並沒有透過 Wi‑Fi 關閉任何真實電器。建議改變用電時間不代表已證明省下多少總用電度數；主要目標是**分散同時用電尖峰**。

## 七、外部 JSON 介面（為未來感測器預留）

`gateway.py` 可以使用選用的外部檔案：

```sh
python3 gateway.py --telemetry telemetry.example.json
```

參考格式：

```json
{
  "timestamp": "2026-11-07T00:00:00+00:00",
  "source": "EXAMPLE_NOT_A_REAL_METER",
  "zones": {"A": 920, "B": 210, "C": 480}
}
```

`zones` 的數字單位為 W。來源時間超過 120 秒，或不存在有效時間時，手機會標示「**資料過期／來源待核對**」。所有外部讀值一律顯示 **「未驗證外部 JSON」**，不會自稱是合格設備量測。此介面**不提供任何繼電器、接觸器、斷路器或用電設備控制指令**。

未來選定合格設備後，需由專業人員依設備原廠協定撰寫獨立驅動程式，實際安裝、隔離、校正和安全測試都不在本原型範圍內。

## 八、分區警示的計算方式與限制

```text
分路示範功率 = 同區被選為同時使用的各電器瓦數之和
分路示範電流(A) = 分路示範功率(W) / 假設電壓(110V)
負載占比 = 分路示範功率 / (110V × 該分路示範 A 值)
高負載示範門檻 = 負載占比達 80%
超限示範門檻 = 負載占比達 100%
```

分路負載排名可以幫助找出相對用電高的地方，但真實住宅應用需要不同電壓、功率因數、電流波形、設備實際資料品質、配線及負載特性。**80% 和 100% 是介面示範門檻，並非真實斷路器跳脫預測、法規或危險程度評估。**

## 九、商品化階段與安全重點

請閱讀 [PRODUCT_PLAN.md](PRODUCT_PLAN.md)。最小可行商品應先聚焦：**合格分路電表 + Wi‑Fi 資料傳輸 + 手機端監測提醒**。不加入直接關斷電箱的能力，降低開發與安全複雜度。

未來涉及用戶用電設備施工，須依法交由適格電器承裝業施作；帶 Wi‑Fi 的商品需評估 NCC 射頻審驗，電力／電器部分需向 BSMI 核對適用檢驗品目，並落實個資、軟體更新及測量可靠性。**這些審驗並未取得，本原型不得當作上市產品。**

## 十、自主學習反思與下一步

我先從一個沒有硬體的用電模型開始，發現「全家用電很多」和「哪一條分路接近負載門檻」是不同問題。於是把家電與分路的關係寫入 JSON，製作手機頁面，用圖表和排序找出示範高負載區域，再提供錯峰使用建議。接著我用 Python 建立本機 Wi‑Fi 網關，理解手機如何從同一網路讀取資料，並留出未來與量測設備對接的 JSON 格式。

目前只完成網頁與網路原型，**沒有接上真正電箱**。下一階段希望先向電機專業人士學習分路量測原理，進行隔離的低電壓教學實驗，再評估以符合安全規範的成品量測器取得家庭分路資料。
