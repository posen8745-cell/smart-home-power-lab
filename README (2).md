# 智慧家庭用電監測與過載警示模擬

基隆私立二信高中・普通科數理班・張博程的自主學習作品。

## 我為什麼想做這個

我想知道：家裡同時使用電鍋、吹風機等電器時，能不能用程式先發現負載太高，再安排電器分開使用？所以我先做一個可以操作的網頁，用假設的電器功率來觀察電流、用電量，以及暫停部分電器後的變化。

**作品想法與功能需求由我提出，程式與介面由 AI 協助完成。我負責操作、觀察結果、提出問題，再請 AI 協助修正。** 目前不是全部由我獨立寫出的程式，我也還在學習裡面的計算與控制方式。

## 怎麼操作

開啟 [網頁模擬器](https://posen8745-cell.github.io/smart-home-power-lab/)，就能開關電器、修改假設的瓦數與優先順序，觀察各分路和總開關的狀態。

- 「播放模擬」：每 1 秒代表模擬經過 15 分鐘，最多 24 小時。
- 「前進 15 分鐘」：手動往前走一步，累計供電量並留下紀錄。
- 「模擬復歸」：先減少負載或啟用智慧管理，符合條件後才能讓跳脫分路恢復。
- 「重設本次紀錄」：保留當下電器設定，清除模擬時間、度數、跳脫與接續排程。
- 「下載 CSV」：至少前進一次後，可下載每一步的實驗數據。

### 兩個實驗

假設電鍋 700W、吹風機 1200W，接在同一條 110V、15A 的分路 A。兩台同時要求 1900W，超過這個模型設定的 1650W 上限。

| 情境 | 網頁會怎麼做 |
|---|---|
| 實驗 A：不管理負載 | 兩台同時啟用，模擬分路 A 跳脫，供電變成 0W。 |
| 實驗 B：智慧管理負載 | 電鍋先用 15 分鐘，吹風機等待；接著電鍋關閉，吹風機再用 15 分鐘。 |

選擇實驗 B 後，按兩次「前進 15 分鐘」，或按播放，就能看到接續使用。這裡的兩段 15 分鐘是為了展示而設定，沒有偵測電鍋是否真的煮好。一般的智慧管理開關只依優先順序暫停超限負載；自動接續排程只用在實驗 B。手動修改電器、分路 A 額定電流或智慧管理開關時，會取消這次接續排程。

實驗 B 第一段用電為 `700 × 0.25 ÷ 1000 = 0.175 度`，第二段為 `1200 × 0.25 ÷ 1000 = 0.300 度`，合計 **0.475 度**。兩台完成相同使用時間時，錯峰主要降低同時使用的功率，不會自動減少總度數。實驗 A 因為跳脫而沒有完成使用，不能把它的 0 度與實驗 B 直接當成節電比較。

## 畫面數字怎麼看

| 名稱 | 意思 |
|---|---|
| 要求功率（W） | 使用者想同時啟用的電器功率合計，可能超過上限。 |
| 供電功率（W） | 經智慧管理與模擬跳脫後，這一步實際供應的模擬功率。 |
| 推估電流（A） | 本頁用 `I = P ÷ V` 計算；假設功率因數為 1。 |
| 用電量（kWh，度） | 每一步用 `P × 時間（小時）÷ 1000` 累加。 |
| 示範電費 | 累計度數乘上自行輸入的單價，不是台電完整計費方式。 |

預設 A 是電鍋與吹風機、B 是照明與風扇、C 是電腦與除濕機。這些都是虛構分路，不是我家實際配電圖，也不能把一條分路直接當成一個房間。

主頁目前使用 **110V、功率因數為 1 的等效模型**。80% 提醒、超過 100% 模擬跳脫都是作品自訂的教學規則；「必要」電器不會被智慧管理自動停用，但必要負載超限時仍可能模擬跳脫。它沒有模擬真實斷路器的延時、啟動電流、配線溫度或其他保護特性。

### 手機展示頁與主頁的差別

`monitor.html` 是另一個獨立的分路排名與錯峰建議展示，**不會同步主頁開關、排程或跳脫狀態**。

- GitHub Pages 上使用 JSON 情境快照，沒有連接家中電表。
- 手機頁「高功率同時使用」顯示 1900W 的負載需求；主頁實驗 A 則顯示模擬跳脫後的 0W 供電。兩者代表不同階段。
- 手機頁現有的錯峰建議以 80% 作為管理目標；主頁一般智慧管理以不超過 100% 為目標，兩頁規則目前不同。
- 手機頁與網關可讀取個別分路的電壓、功率因數；主頁仍使用上述固定的等效模型。不能直接把混合 110V／220V 資料當成主頁已正確支援。

## 手機 Wi-Fi 原型

若只想看網頁模擬，不必執行 Python。若要試同一個 Wi-Fi 下的手機原型，電腦需要保留儲存庫原有的 `gateway.py`、`monitor.html`、`mock_panel.json` 等檔案，再執行：

```sh
python3 gateway.py
```

Windows 也可依安裝情況使用 `py gateway.py`。電腦和手機連上同一個可信任的 Wi-Fi 後，用手機開啟終端機顯示的網址，再輸入本次六位示範碼。網關預設每 5 秒提供一次虛構資料；這不是已連上家用電箱的證明。

GitHub Pages 只提供靜態網頁，不會執行 `gateway.py`。這個區域網路原型沒有正式產品的連線安全設計，不應開放到公開網路。

原有外部 JSON 讀取介面也保留：

```sh
python3 gateway.py --telemetry telemetry.example.json
```

範例不是實測資料。外部檔案需有帶時區的時間與完整分路資料；來源過期或無法讀取時，手機頁會顯示資料無效。本次只修改 `index.html` 和 `README.md`，沒有修改手機頁、網關或外部資料格式。

這份作品目前能展示程式的計算與控制想法，還沒有接入真實感測器，也沒有控制真實家電。我希望先把模擬結果看懂、把問題找出來，再研究如何在老師與專業人員協助下驗證。它不能用來判斷家中配線、插座或斷路器是否安全。
