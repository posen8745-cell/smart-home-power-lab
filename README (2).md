# 智慧家庭用電監測與過載警示模擬

基隆私立二信高中・普通科數理班・張博程的自主學習作品。

## 我為什麼想做這個

家中一樓餐廳使用高功率電器時，常會發生跳電。這讓我想到：能不能用程式觀察目前的用電負載，在負載太高時提醒使用者，或讓部分電器晚一點使用，避免全部擠在同一個時間？

所以我先做一個可以操作的網頁，用假設的電器功率來觀察電流、用電量，以及錯開使用後的變化。我想先透過模擬，看看這個想法能不能降低同時用電的尖峰。家中實際跳電原因與迴路配置目前尚未透過量測確認；家中餐廳的電器包括氣炸燒烤爐、微波爐、電鍋、IH 飯鍋與飲水機。網頁改用這五項電器，但瓦數、使用時間和同分路設定仍是示範，不是家中餐廳的實測資料。

**作品想法與功能需求由我提出，程式與介面由 AI 協助完成。我負責操作、觀察結果、提出問題，再請 AI 協助修正。** 目前不是全部由我獨立寫出的程式，我也還在學習裡面的計算與控制方式。

## 怎麼操作

開啟 [網頁模擬器](https://posen8745-cell.github.io/smart-home-power-lab/)，就能開關電器、修改假設的瓦數與優先順序，觀察各分路和總開關的狀態。

- 「播放模擬」：每 1 秒代表模擬經過 15 分鐘，最多 24 小時。
- 「前進 15 分鐘」：手動往前走一步，累計供電量並留下紀錄。
- 「模擬復歸」：先減少負載或啟用智慧管理，符合條件後才能讓跳脫分路恢復。
- 「重設本次紀錄」：保留當下電器設定，清除模擬時間、度數、跳脫與接續排程。
- 「下載 CSV」：至少前進一次後，可下載每一步的實驗數據。

### 餐廳的五項電器與兩個實驗

我把家中餐廳使用的五項電器放進模擬。下面的瓦數只是為了展示而設定，可以在畫面修改，不能當作我家電器的實際規格。

| 電器 | 假設輸入功率 |
|---|---:|
| 氣炸燒烤爐 | 1500W |
| 微波爐 | 1100W |
| 電鍋 | 700W |
| IH 飯鍋 | 1200W |
| 飲水機（加熱階段） | 700W |
| 同時啟用合計 | **5200W** |

微波爐的欄位要填額定輸入功率，不能直接把微波輸出功率當成耗電功率。飲水機目前只用一個加熱功率來示範，沒有模擬待機、保溫或間歇加熱；一般情境若一直保持開啟，程式也會持續按設定瓦數累計，不能把這個結果當成飲水機的實際全天耗電量。

為了看出差別，這版先假設五項電器同接一條 110V、15A 的虛擬分路 A，上限是 1650W。**目前還沒有確認家中這五項電器是否真的在同一條迴路，也沒有量測確認跳電原因。** 同在餐廳不代表一定同一分路。

| 情境 | 網頁會怎麼做 |
|---|---|
| 實驗 A：五項同時使用 | 要求 5200W，超過這個模型的分路上限，模擬分路 A 跳脫，供電變成 0W。 |
| 實驗 B：五項錯開使用 | 依序模擬氣炸燒烤爐、微波爐、電鍋、IH 飯鍋、飲水機加熱，每次只供應其中一項。 |

選擇實驗 B 後，按五次「前進 15 分鐘」，或按播放，就能看到每項結束後，下一項接續使用。每項 15 分鐘只是為了展示而假設的時間，不是食物煮熟、飲水機達到水溫所需的實測時間，也沒有真的偵測電器是否完成。

預設示範完成五步時，合計用電為 `(1500 + 1100 + 700 + 1200 + 700) × 0.25 ÷ 1000 = 1.300 度`。同時功率最高降到單一項的 1500W；錯開使用沒有自動減少完成相同使用量的度數。實驗 A 因為跳脫而沒有完成使用，不能把它的 0 度與實驗 B 直接當成節電比較。

一般的智慧管理開關依優先順序暫停超限負載；實驗 B 則使用固定的五項接續順序。飲水機預設為「必要」，一般智慧管理不會自動停用它；實驗 B 中的飲水機則是一筆排在最後、使用 15 分鐘的虛擬加熱工作。手動修改電器、分路 A 額定電流或智慧管理開關時，會取消接續排程。

## 畫面數字怎麼看

| 名稱 | 意思 |
|---|---|
| 要求功率（W） | 使用者想同時啟用的電器功率合計，可能超過上限。 |
| 供電功率（W） | 經智慧管理與模擬跳脫後，這一步實際供應的模擬功率。 |
| 推估電流（A） | 本頁用 `I = P ÷ V` 計算；假設功率因數為 1。 |
| 用電量（kWh，度） | 每一步用 `P × 時間（小時）÷ 1000` 累加。 |
| 示範電費 | 累計度數乘上自行輸入的單價，不是台電完整計費方式。 |

本版只展示餐廳五項電器與虛擬分路 A，沒有計入家中其他用電。總開關 30A 與分路 A 15A 仍為教學假設，不是我家實際配電規格。

主頁目前使用 **110V、功率因數為 1 的等效模型**。80% 提醒、超過 100% 模擬跳脫都是作品自訂的教學規則；「必要」電器不會被智慧管理自動停用，但必要負載超限時仍可能模擬跳脫。它沒有模擬真實斷路器的延時、啟動電流、配線溫度或其他保護特性。

### 手機展示頁與主頁的差別

`monitor.html` 仍保留原有的獨立分路示範，**尚未改成餐廳這五項電器，也不會同步主頁開關、排程或跳脫狀態**。

- GitHub Pages 上使用 JSON 情境快照，沒有連接家中電表。
- 手機頁仍用原有電器與 1900W 情境；餐廳主頁則用五項電器與 5200W 情境，兩頁不是同一組測試。手機頁主要顯示負載需求，餐廳主頁另模擬跳脫後的供電。
- 手機頁現有的錯峰建議以 80% 作為管理目標；主頁一般智慧管理以不超過 100% 為目標，兩頁規則目前不同。
- 手機頁與網關可讀取個別分路的電壓、功率因數；主頁仍使用上述固定的等效模型。不能直接把混合 110V／220V 資料當成主頁已正確支援。

## 手機 Wi-Fi 原型

若只想看網頁模擬，不必執行 Python。若要試同一個 Wi-Fi 下的手機原型，電腦需要保留儲存庫原有的 `gateway.py`、`monitor.html`、`mock_panel.json` 等檔案，再執行（仍為原有的獨立情境）：

```sh
python3 gateway.py
```

Windows 也可依安裝情況使用 `py gateway.py`。電腦和手機連上同一個可信任的 Wi-Fi 後，用手機開啟終端機顯示的網址，再輸入本次六位示範碼。網關預設每 5 秒提供一次虛構資料；這不是已連上家用電箱的證明。

GitHub Pages 只提供靜態網頁，不會執行 `gateway.py`。這個區域網路原型沒有正式產品的連線安全設計，不應開放到公開網路。

原有外部 JSON 讀取介面也保留：

```sh
python3 gateway.py --telemetry telemetry.example.json
```

範例不是實測資料。外部檔案需有帶時區的時間與完整分路資料；來源過期或無法讀取時，手機頁會顯示資料無效。本次只修改 `index.html` 和 `README.md`，沒有修改手機頁、網關或外部資料格式。

上傳更新時，用新的 **`index.html`** 和 **`README.md`** 覆蓋同名檔案，其他檔案保留。首頁名稱必須正好是 `index.html`。

| 原有檔案 | 用途 |
|---|---|
| `index.html` | 配電箱、電器開關、模擬跳脫、接續使用、功率曲線與 CSV。 |

| `monitor.html` | 手機分路排名與用電建議。 |

| `test_gateway.py` | 原有網關的程式測試。 |

這次將首頁改成家中一樓餐廳的五項電器，保留先前的額定電流同步顯示、要求與供電功率區分、模擬跳脫、接續使用及 CSV。原有 JSON 可以保留；重新讀取 JSON 後，首頁仍會套用內建的餐廳五項電器。

這份作品目前能展示程式的計算與控制想法，還沒有接入真實感測器，也沒有控制真實家電。我希望先把模擬結果看懂、把問題找出來，再研究如何在老師與專業人員協助下驗證。它不能用來判斷家中配線、插座或斷路器是否安全。
