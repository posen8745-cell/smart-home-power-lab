# 智慧家庭分區用電監測與過載警示

基隆私立二信高中・普通科數理班・張博程的自主學習作品。

## 我為什麼想做

家中一樓餐廳有氣炸燒烤爐、微波爐、電鍋、IH 飯鍋和飲水機。同時使用高功率電器時，20A 總開關曾跳脫，一樓整層就沒電。我因此想到：能不能先看出目前是哪條分路的負載太高，再提醒家人錯開使用？

我先做一個虛擬配電箱，讓人從「總開關 → 三條分路 → 各項電器」看用電變化，再比較沒有管理和啟用負載管理的差別。

**想法與功能需求由我提出，程式與介面由 AI 協助完成。我負責操作、觀察結果、提出問題，再請 AI 協助修正。** 目前不是全部由我獨立寫出的程式，我也還在學習計算、量測和控制的差別。

## 最簡單的操作

依序按首頁上方三個情境，不需要先修改設定，也不必播放時間。

| 按鈕 | 想觀察的事情 | 預設結果 |
|---|---|---|
| 1. 一般用電 | 先看總開關與三條分路 | 照明、風扇、電腦、除濕機，共 507W |
| 2. 高功率同時使用 | 加入氣炸燒烤爐與微波爐 | 分路 A 要求 2600W，超過 1650W 模擬上限，A 跳脫；B、C 繼續供應 507W |
| 3. 啟用負載管理 | 相同需求，讓程式依優先等級調整 | 暫停微波爐，A 供應氣炸燒烤爐 1500W；全箱供電 2007W |

每個按鈕都會重新載入該情境，清除前一情境的時間、度數與紀錄。這三步是比較情境，不是必須照順序才能操作。

比較時要分清楚：**要求功率**是想一起使用的功率；**供電功率**是經管理與模擬跳脫後剩下的功率。第二個情境供電較少，是因為 A 跳脫，不能把它當成比較節電。第三個情境也只是先暫停微波爐，並不代表已完成加熱。

## 保留原本的作品內容，減少主畫面的設定

主畫面保留配電箱、三條分路、電器開關、負載警示與管理結果。電器的瓦數及優先順序預設收起，勾選「顯示電器進階設定」才顯示。

自行試其他組合時，可切換電器開關。若分路已模擬跳脫，先關掉部分電器或啟用管理，再按「模擬復歸」。復歸只是網頁操作，不是真實電箱的操作教學。

以下功能放在可展開區塊，第一次展示不需要操作：

- JSON 情境與示範資料。
- 分路 A 額定電流與示範電價。
- 前進 15 分鐘、播放時間、度數累計。
- 24 小時功率曲線、事件紀錄、CSV、計算方式。

前進一次才把當下供電維持 15 分鐘的用電量計入紀錄；播放每 1 秒前進一次，最多 24 小時。這不是電器真的需要使用的時間，也沒有固定讓五項電器依序排隊。改設定只更新當下結果，不會回頭改寫先前的紀錄。

## 虛擬配電箱怎麼分

| 項目 | 本頁示範設定 | 用途 |
|---|---|---|
| 總開關 | 20A | 依家中描述呈現，實際配電形式仍未核對 |
| 分路 A | 110V、15A | 餐廳五項電器，先假設共用一條分路 |
| 分路 B | 110V、10A | LED 照明、風扇 |
| 分路 C | 110V、15A | 電腦、除濕機 |

分路不一定等於房間。同在餐廳，也不代表真的接在同一條分路；這些標籤是虛構的，沒有量測核對家中接線。不能把分路額定電流直接相加當成總開關可供電量。

| 餐廳電器 | 假設輸入功率 |
|---|---:|
| 氣炸燒烤爐 | 1500W |
| 微波爐 | 1100W |
| 電鍋 | 700W |
| IH 飯鍋 | 1200W |
| 飲水機（加熱階段） | 700W |

氣炸燒烤爐是本次比較的主要高功率電器。瓦數都是可修改的假設值，不是家中機型的實測規格；微波爐應看輸入功率，飲水機沒有模擬待機、保溫和間歇加熱。

## 程式做了什麼

本頁以 `I = P ÷ V` 估算電流，固定使用 110V、功率因數 1 的簡化模型。度數則以 `E = P × t ÷ 1000` 累加，P 是瓦、t 是小時。

超過分路額定的 80% 會顯示提醒；超過 100% 會模擬跳脫。這是作品自訂規則，沒有模擬真實斷路器的延時、啟動電流或保護協調，不能預測實際何時跳電。本模型先處理分路跳脫，再檢查仍供電的分路是否超過總開關上限，並不代表現場一定以這個順序跳脫。

啟用負載管理時，先依「可延後 → 一般」暫停模擬供電，保留「必要」；同級時先暫停瓦數較高者。若必要負載仍超限，也會模擬跳脫。負載減少後會重新計算供電，沒有判斷食物是否煮熟，也不會操作真實家電。

錯開使用主要降低同時用電的功率，不會自動減少完成相同工作所需的度數。示範電費是度數乘自訂單價，並非正式電價計費。

## JSON、手機頁與 Wi-Fi 原型

首頁會讀取同層的 `mock_panel.json`，參考原本三條分路的額定電流；電器清單、三個情境與 20A 總開關設定內建在本頁。沒有 JSON 或格式不支援時，會標明改用內建備援資料，不會假裝讀取成功。

本頁只支援這個三條 110V 分路的簡化示範，不宣稱支援任意真實電箱資料。若更改 JSON 的分路額定，結果可能和上表的預設比較不同。

原有 `monitor.html` 與 `gateway.py` 保留為另一個 Wi-Fi 手機原型：

1. 只看展示：開啟 `monitor.html`，看 JSON 虛構情境。
2. 要做區域網路測試：電腦保留原儲存庫檔案，執行 `python3 gateway.py`，手機與電腦連同一個可信任網路。
3. 在手機開啟終端機顯示的網址，依原型畫面輸入本次示範碼。

GitHub Pages 不會執行 Python。手機頁仍是原本的獨立情境，不會同步首頁的電器開關、20A 設定、管理與跳脫結果。Python 原型也未連接合格電表，不代表已取得家中真實用電資料；不要把區域網路原型開放到公開網路。

「負載偏高時先通知手機」仍是後續想研究的方向。這版沒有實際遠端推播，也沒有全天候背景監測。
